局域网 · 无需联网 · 零账号 · 跨平台

互传 · 局域网任意设备直传

手机、电脑之间文件和文字双向直传：同一 Wi-Fi 内点对点，不用数据线，不用云盘，不经过任何服务器。Mac、Windows、Linux 都能当主机，任何带浏览器的设备都能当访客。

角色与概念

整套系统只有两个角色，读完这一段就能上手：

角色是谁做什么
主机
跑服务的一端		 装了本应用的 Mac，或跑了 start.bat / start.sh 的 Windows / Linux 电脑 开一个局域网服务；收文件进收件箱；把要发出去的东西放进发件箱等对方来取
访客
开网页的一端		 任何能开浏览器的设备：安卓 / iOS 手机、平板、另一台电脑。什么都不用装 用浏览器打开主机的地址：上传文件、发文字给主机；取走主机放进发件箱的内容 
访客 → 主机   访客浏览器 ──上传／粘贴──▶ 接收服务 ──▶ 收件目录 ~/Downloads/android-inbox

主机 → 访客   主机放进发件箱 ──等待取件──▶ 访客页面点「下载」／「复制全文」

所有流量只走局域网，不出网、不注册、不登录。页面上显示的主机名、平台、目录都是动态取自服务端的 —— 主机是 Mac、Windows 还是 Linux，文案自动跟着变。

为什么主机 → 访客是「等你去取」而不是「弹窗推给你」：局域网下的网页没有被动接收推送的通道（Web 推送要求 HTTPS + 推送服务器，而这里走的是明文 HTTP）。所以主机发的东西会先排进发件箱，访客打开页面就能看到并取走。反正访客本来也要打开页面才能下载，实际体验差别很小。

快速开始

第一步：把主机跑起来

平台启动方式说明
macOS 双击「FileRelay.app」 不占 Dock，菜单栏右侧出现一个彩色磁贴小图标。后台服务随之启动
Windows 双击 start.bat 自动找 py -3 或 python（需 Python 3.8+，安装时勾选 Add Python to PATH）。关闭窗口即停止服务
Linux / macOS 终端 ./start.sh 自动找 python3（3.8+）。前台运行，Ctrl+C 停止

启动横幅会打印两条地址：本机控制台（http://127.0.0.1:端口/）和局域网地址（给其他设备用）。端口默认 8765，被占用自动顺延，以横幅和运行时信息为准。

第二步：让访客连上来

  1. 主机上打开二维码：Mac 点菜单栏图标 →「显示二维码」；任何平台都可以在本机控制台点「显示二维码」。
  2. 手机与主机连同一个 Wi-Fi，用相机或微信扫码，浏览器就会打开互传页。
  3. 另一台电脑当访客？直接在它的浏览器里打开横幅里那个局域网地址，效果与手机相同。

主机端：本机控制台（全平台）

用主机自己的浏览器打开 http://127.0.0.1:端口/，页面会自动切换成控制台视图 —— 主机的操作台：

  • 收件箱 / 发件箱双栏：左边看收到了什么（可一键打开目录），右边管要发出去的。发件箱栏有拖放区，把文件拖进去＝发送，也可以点「发射剪贴板文字」把主机剪贴板内容发给访客。
  • 两个剪贴板开关（页面底部）：「允许对方读取本机剪贴板」与「自动写入收到的文字」，勾选即时生效，不用重启。
  • 显示二维码 / 使用说明（就是本手册）/ 退出服务。
控制台只有主机能开：它只对 127.0.0.1 这类本机地址生效 —— 其他设备（包括同一 Wi-Fi 里的电脑）访问局域网地址时，看到的仍是普通互传页，打不开控制台，也碰不到「退出服务」「打开目录」这些本机操作。局域网里的另一台电脑要传文件，直接用互传页就行：上传、发文字、收发件箱全都能用。

主机端：菜单栏（macOS 专属）

Mac 版额外有一套菜单栏，日常高频操作不用开浏览器：

菜单项作用
显示二维码弹出原生窗口显示二维码 + 当前局域网地址。换 Wi-Fi 后地址会自动刷新
发送剪贴板文字到手机把 Mac 剪贴板里的文字放进发件箱，对方页面刷新后就能看到并复制
发送文件到手机…弹出文件选择框（可多选），选中的文件会出现在对方的收件列表里
打开发送目录打开发件箱目录。往里拖文件＝发送，连菜单都不用点
清空发件箱…删掉还没被取走的内容。对方已下载的副本不受影响
待发 N 项 · 对方在线／离线一眼看到还有多少东西等着取，以及对方页面当前是否连着
打开接收目录在 Finder 中打开收件目录
复制接收地址把地址复制到剪贴板，方便手动发给对方
最近接收显示最后一次收到的内容与时间，每 2 秒自动刷新
自动写入收到的文字默认开启。对方发来的文字直接进 Mac 剪贴板——手机上复制、Mac 上 Cmd+V 就完事

服务端口显示实际在用的端口。默认 8765，被占用时自动顺延，这里能看到换成了哪个
使用说明 / 退出打开本手册 / 退出应用并停掉后台服务

访客端能做什么

上传文件

  • 点「选择文件」可一次选多个，支持图片、视频、文档、压缩包等任意类型；也可从其他 App 拖进来。
  • 每个文件有独立的进度条，传完显示成功；文件按原名保存，不改名、不压缩，重名自动加序号。

发送文字

  • 「传文字」页签的输入框：长按 → 粘贴，内容立刻发到主机；也可以手动打字，比如网址、验证码、一段地址。
关于「自动读取剪贴板」：浏览器出于安全策略，禁止网页在非 HTTPS 环境下静默读取剪贴板。所以这里是「你一粘贴就自动发走」，而不是「后台偷偷读」。这是所有局域网方案的共同限制，不是本应用的缺陷。

收主机发来的东西

「从对方收」页签（按主机名动态显示）列出对方放进发件箱的全部内容；有东西没取时，页签上显示红色数字角标。

  • 下载文件：点条目右侧的「下载」（或直接点这一行），文件进设备的下载目录。
  • 打包下载：条目多时点「打包 zip」一次全取走。
  • 看文字、复制：文字条目点「查看」展开全文，再点「复制全文」粘到别的 App。
  • 取完清空：都收好后点「收下并清空」，主机上的待发副本随即删除（对方已下载的不受影响）。
页面开着才会自动刷新：手机浏览器不允许后台网页持续刷新，所以角标只在页面处于前台时更新。切回页面、或点一下收件页签，都会立刻刷新一次。主机发来的东西会一直排队（默认保留 24 小时，上限 200 项），晚点来取也不会丢。

读主机此刻的剪贴板

发件箱是「主机主动发来的东西排队等取」，而剪贴板是主机此刻手上正拿着的，所以不进队列、不留档 —— 点一次拿一次。

  1. 主机先放行：Mac 在菜单栏、其他平台在本机控制台页底部，勾上「允许对方读取本机剪贴板」。
  2. 访客切到收件页签，最上面那块就是「对方剪贴板」（显示主机的实际名称）。
  3. 点「读取」，主机当前的剪贴板文字会显示在下方，点「复制」即可粘到别的 App。
  • 这块区域如实显示开关状态：主机还没放行时直接写「还没允许」并告诉你去哪开；放行后写成「已允许」。
  • 读出来的内容只显示在页面上，不落盘、不进队列 —— 一次性动作，不留任何文件。
为什么默认是关的：剪贴板里经常有密码、验证码、私聊片段，而局域网内任何拿到地址的设备都能读 —— 所以必须由你在主机上逐次明确开启。用完把勾去掉即可；服务端每次请求都现读开关，改完立刻生效、不用重启。

收到的内容放在哪、发出去的放在哪

收件目录
~/Downloads/android-inbox（Windows 即 %USERPROFILE%\Downloads\…；下载目录被 OneDrive 等重定向时，以启动横幅打印的实际路径为准）
收到的文件
按原文件名保存，重名自动加序号（如 photo(1).jpg），不覆盖
收到的文字
追加写入收件目录下的 clipboard.log，每条带时间戳分隔；同时按开关决定是否进主机剪贴板。记录只滚动保留最近 200 条，更早的自动丢弃 —— 传文字常含验证码、密码这类临时内容，不该永久留在盘上。主机可随时在控制台页底「清空文字记录」或菜单栏「清空文字记录…」一键清空
状态文件
收件目录下的 __last.json，供菜单栏/控制台显示「最近接收」，可忽略
发件箱
~/Downloads/android-outbox。要发的东西都先放这儿等对方来取；对方点「收下并清空」后自动删除，超 24 小时没人取也会自动清理，队列上限 200 项
开关文件
~/.androidtransfer/flags/，记录两个剪贴板开关的状态，可忽略
运行时信息
~/.androidtransfer/runtime，记录实际端口、进程号与访问地址。服务退出时自动删除，可忽略

常见问题

现象原因与解决办法
访客打不开页面 依次确认：① 两端在同一个 Wi-Fi（别一个连 5G 一个连访客网络）；② 路由器没开「AP 隔离 / 客户端隔离」；③ 主机防火墙没拦传入连接（Windows 首次启动弹的防火墙询问必须点「允许访问」——点了取消后 127.0.0.1 仍能打开，看起来"服务正常"，实则局域网全断）
提示端口被占用 / 端口不是 8765 不用管。服务会自动顺延到下一个可用端口（8765 → 8766 → …），横幅、二维码、「复制接收地址」用的都是实际端口。功能完全不受影响
Mac：双击提示「已损坏」或「来自身份不明的开发者」 网络传输的应用会被打上隔离属性，执行一次即可：
xattr -dr com.apple.quarantine "/Applications/FileRelay.app"
Mac：Finder 里图标还是旧的 系统图标缓存未刷新。在 访达 中执行 killall Finder，或把应用拖到桌面再拖回
收不到系统通知 macOS：到 系统设置 → 通知 找到本应用，打开「允许通知」。Linux：确认装了 notify-send（多数发行版自带）。Windows：个别精简系统弹窗不显示，不影响传输本身
收到的文件找不到 以启动横幅里打印的实际收件目录为准 —— 下载文件夹被 OneDrive 等重定向的系统，服务会自动尝试备选位置
发件箱里的文件一直留着 正常，它在等对方来取。对方点「收下并清空」后立即删除；不点的话超过 24 小时自动清理（上限 200 项）。也可随时手动清空
文字发过去了，主机剪贴板里没有 检查「自动写入收到的文字」开关（Mac 在菜单栏、其他平台在控制台页底，打勾＝开启）。关掉后文字仍会存进 clipboard.log（滚动保留最近 200 条），只是不进剪贴板
访客点「读取」说还没允许 这个开关默认关闭，必须先在主机上放行（见「读主机此刻的剪贴板」）。放行后再点一次「读取」即可，不用重启服务
「读取」显示「剪贴板现在是空的」 如实反馈 —— 主机此刻的剪贴板确实没有文本。剪贴板里若是图片或文件，本应用只处理文字，显示为空
安卓下载时提示「文件可能有害」 安卓 Chrome 对非 HTTPS 地址下载的例行提示，选「仍然下载」即可。局域网自建服务拿不到可信证书，这条提示绕不过去
点「复制全文」没反应 浏览器不允许非 HTTPS 页面用新版剪贴板接口，应用会自动退回兼容方式；万一也被拦，按钮会变成「请长按上方文字手动复制」
换了 Wi-Fi 后地址失效 正常。重新打开二维码即可，它每次都读当前地址

端口是怎么选的

  1. 先试首选端口（默认 8765）。
  2. 若被占用，依次试 8766、8767… 最多向后探 20 个，取第一个能真正绑上的。
  3. 把实际端口写进 ~/.androidtransfer/runtime；二维码、访问地址一律以它为准。
  4. 服务退出时自动清掉这个文件，不留下误导下次启动的旧端口。
不用担心记错端口：你从来不需要手动输端口——扫码或「复制接收地址」拿到的地址里已经包含正确端口。Windows 首次启动若弹防火墙询问，点「允许访问」即可让局域网设备连进来。

高级设置

改端口或目录（环境变量，三个平台通用）

PORT=9000 ./start.sh            # 首选端口；被占用自动顺延
PORT_SPAN=5 ./start.sh          # 限制顺延范围（只允许 8765～8769）
INBOX=… OUTBOX=… ./start.sh     # 自定义收件 / 发件目录
OUTBOX_TTL=86400 OUTBOX_MAX=200 ./start.sh   # 发件箱保留秒数 / 队列上限

Windows 用 set PORT=9000（或 PowerShell 的 $env:PORT=9000）后再跑 start.bat。Mac 的 .app 里这些值写在启动器 Contents/MacOS/AndroidTransfer 中，右键 → 显示包内容即可编辑。

不要为了「固定端口」去关掉顺延。把它设成首选值就够了：真被占用时顺延能保证服务照常可用，而固定端口只会让你多遇到一次「打不开页面」。

开启访问口令

TOKEN=auto ./start.sh   # 首次自动生成口令并记住，重启不变

默认同一 Wi-Fi 下任何设备都能上传。开启口令后，二维码和「复制接收地址」都会自动带上 ?token=…，访客扫码即可，无需手动输入。开启后发件箱的读取和下载同样受口令保护。

开机自动启动

  • macOS：系统设置 → 通用 → 登录项，点「+」加入「FileRelay.app」。
  • Windows：Win+R 输入 shell:startup，给 start.bat 建一个快捷方式放进去。
  • Linux：桌面环境的「自启动」设置里加一条 start.sh，或按发行版惯例写 systemd user unit。

多台主机怎么用

每台电脑各自跑一份就好 —— 两台可以都用 8765 端口，因为 IP 不同：

  • 每台各有自己的二维码，扫哪台就传到哪台，天然解决「发到哪台」的选择问题。
  • 互不干扰，收件目录各自独立在本机。
  • 端口冲突只在同一台机器上才会发生，跨机器不冲突。

安全须知

  • 本服务只监听局域网，不做端口转发，不对外暴露。
  • 公共 Wi-Fi（咖啡厅、酒店）下使用时，建议开启 TOKEN 口令，避免同网段其他人上传文件或读走你发出去的内容。
  • 本机控制台只对 127.0.0.1 生效，「打开目录」「退出服务」这类本机操作无法被局域网里的其他设备调用。
  • 「允许对方读取本机剪贴板」默认关闭：剪贴板里经常有密码、验证码，只有明确需要时才打开。
  • 反过来，访客发来的文字默认会自动写进主机剪贴板（方便直接粘贴）。若担心覆盖你手上的复制内容，把「自动写入收到的文字」关掉即可。
  • 用完即可退出（Mac 菜单栏点「退出」；其他平台关窗口 / Ctrl+C / 控制台「退出服务」），服务随之停止，不留后台进程。

卸载

  1. 先停服务：Mac 菜单栏点「退出」；Windows 关掉 start.bat 窗口；Linux Ctrl+C。
  2. macOS：把「FileRelay.app」从 /Applications 拖到废纸篓。Windows / Linux：删除项目目录即可。
  3. 如不再需要已收到的文件，可一并删除收件目录与发件箱（~/Downloads/android-inbox、~/Downloads/android-outbox）。
  4. 可选：删掉 ~/.androidtransfer（运行时信息与开关文件目录）。
